# v0.16 PCI DPDK Runner Contract

更新时间：2026-10-02

本文定义真实 PCI DPDK 性能 runner 的最小接入契约。没有满足全部前置条件
时，runner 必须返回结构化 `SKIP` 或 `ENVIRONMENT-OPEN`，不得用 QEMU、
VMware polling-only 或合成流量填充性能 PASS。

## 前置条件

- Debian trixie 或兼容的 Linux runtime；
- 一块受 VPP 26.10 DPDK PMD 支持的 PCI Ethernet NIC；
- 目标设备已绑定 `vfio-pci` 或明确允许的 `uio` 驱动；
- `/dev/vfio/vfio`（VFIO 路径）和非零 HugePages；
- 可执行 `vpp`/`vppctl` 与可读 `dpdk_plugin.so`；
- 独立流量发生器，首测使用 64-byte、单核、至少两个独立 5-tuple 的双向流；
- runner 能将结果写入 `DPDK_RESULT_FILE`。
- 每次运行必须通过 `DPDK_PCI_BDF` 指定正在验收的 Ethernet PCI function；
  预检结果须记录 vendor/device ID 与当前绑定驱动。未指定 BDF 时不得继续。
- `DPDK_ISO` 必须指向被测镜像；runner 从 ISO 的
  `initramfs.cpio.gz:/etc/danos/build-info.env` 提取 source commit/dirty marker。
  缺少 build identity 或 `source_dirty != 0` 时只能 `SKIP/OPEN`，不可签性能 PASS。
- 环境预检本身只证明 runner 可进入性能测试阶段；没有流量发生器测量时，
  `performance_status` 必须保持 `ENVIRONMENT-OPEN`，不能把预检 PASS 当性能 PASS。

RTL8168 (`10ec:8168`) 在当前宿主不作为 DPDK 通过设备；本机 lane 继续
保持 `ENVIRONMENT-OPEN`。

## 接入命令

```sh
DPDK_PCI_DRIVER=uio_pci_generic \
DPDK_ISO=build/danos-open-v0.16.0-rc1-i211-dpdk-polling-runner-r3.iso \
DPDK_RESULT_FILE=build/v016-dpdk-preflight.env \
DPDK_PCI_BDF=0000:01:00.0 \
bash danos-test/integration/run_v016_release_gate.sh
```

I211 设备可按 runner 实际绑定设置 `DPDK_PCI_DRIVER=uio_pci_generic`；BDF
必须来自该机器的 `lspci -Dnnk` 输出，例如 `0000:01:00.0`。PCI 预检通过时
脚本返回 `ENVIRONMENT-OPEN`，直到统一性能字段由真实流量发生器填充。
当前可用于 I211 实机启动验证的 clean-provenance polling ISO 为
`build/danos-open-v0.16.0-rc1-i211-dpdk-polling-runner-r3.iso`（SHA256
`017e9ca96fa3222ac4f70084264ac796f23ca805d1132fdc7afc5b5da54eeaf0`）；它配置
`0000:01:00.0`/`0000:02:00.0` 和 `no-rx-interrupts`，并在启动时按预期将精确匹配的
I211 交给 `uio_pci_generic`。QEMU USB 键盘 smoke 通过，QEMU 串口因无目标 BDF 而报告
binding fail-closed；尚未在 I211 实机验证绑定成功，不能据此推断实机键盘或网卡验收通过。实际 runner 上
应先确认 ISO 启动和 tty1 输入，再按上方命令运行预检；目前绑定
`uio_pci_generic` 的两块 I211 可用 `DPDK_PCI_BDF=0000:01:00.0` 做首卡预检。
历史镜像 `danos-open-v0.16.0-rc1-i211-dpdk-usb-hid-final.iso` 没有嵌入
`build-info.env`，身份提取器会明确返回 `SKIP`；必须用包含 clean build metadata 的
新 ISO 再测。性能结果的 `commit` 表示 ISO source commit，`runner_commit` 仅记录
预检工具 checkout。

外部流量发生器应把首轮 64-byte 双向结果导出为 `key=value` 文件，填写性能
schema 中的包数、loss、时长、PPS、Mbps、延迟、CPU 和两个 ECMP bucket。用
下面的校验器绑定预检、ISO/commit 身份，并按本 runner 明确设定的门限判定：

```sh
python3 danos-test/integration/record_dpdk_perf_result.py \
  --preflight build/v016-dpdk-preflight.env \
  --measurement build/i211-64b-measurement.env \
  --out build/i211-64b-accepted.env \
  --min-pps "$I211_MIN_PPS" \
  --max-loss-pct "$I211_MAX_LOSS_PCT" \
  --max-cpu-pct "$I211_MAX_CPU_PCT"
```

门限必须按流量发生器、端口速率和 runner CPU 能力预先确定。省略任一门限时，
结果只记录为 `ENVIRONMENT-OPEN`；身份不匹配、字段缺失或门限不满足会拒绝
签发 PASS。确定性单元测试由统一 v0.16 release gate 自动运行。

gate 会同时产生：

- `build/v016-release-gate.env`：总 gate 和环境状态；
- `build/v016-dpdk-preflight.env`：PCI lane 的统一结果字段；
- `build/v016-vmware-vmxnet3.env`：虚拟化 packet baseline 对照。
- `record_dpdk_perf_result.py`：把外部测量绑定到 preflight 的目标 PCI ID、ISO
  digest 和 commit，并根据显式门限判定性能状态。

## 首轮性能证据

首轮只接受 64-byte 单核结果；结果必须填写统一 schema 的 `pps`、`mbps`、
`loss_pct`、`rtt_p50_us`、`rtt_p99_us`、`cpu_pct`、两个 ECMP bucket 计数、
commit 和 ISO digest。通过首轮后再执行多核、长稳和 ECMP 分布测试。

`flows` 必须至少为 2；单个 5-tuple 通常只映射到一个 ECMP bucket，不能证明
双路径有流量。`ecmp_bucket_0/1` 必须是受测时间窗内两个路径各自的 packet-counter
增量（测试后减测试前），且两个增量均大于 0；绝对累计计数或测试之外的流量不能
用来满足该条件。校验器会拒绝单流数据及缺失任一路 bucket 的测量。

正式 `v0.16.0` 发布前，PCI lane 必须有独立 `PASS` 证据；缺失 runner 时
正式版本保持未发布状态。
