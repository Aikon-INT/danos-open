## 2026-09-25 增量证据

- `build/qemu-frr-vpp-topology-16` 使用 Debian trixie、FRR 10.3 和当前双端口
  VPP ISO 完成真实长连接验收。
- FRR route-cycle 的 add/withdraw/restore 返回码均为 0，DANOS 串口依次记录
  `command=31`、`command=32`、`command=31`，并对三次事件执行 VPP route add/delete/add。
- 修正 FRR route type 订阅为 `4,9`（static、BGP）；此前 ISO 的 `3` 无法覆盖
  FRR 10.3 static 动态通知。
- 本证据关闭 IPv4 动态 add/withdraw/restore gate，但不等同于 BGP/OSPF 邻居、
  多流报文分布或重启恢复完成。
- topology-26 进一步完成真实 VPP SIGTERM/重启：串口记录
  `VPP-RESTART-TEST PASS`，并在新 API socket 上恢复 `198.51.100.0/24`，
  同时 bridge 日志记录 `replay attempted=1 failed=0`。

## 验收分层

- L0：单元、wire、并发、fuzz、确定性测试。
- L1：特权 FRR/VPP 控制面及 FIB 编程。
- L2：QEMU/Docker 报文级转发和恢复。
- L3：真实 PCI/VFIO/uio、DPDK 性能和多流分布。

当前 L0/L1 已基本完成，L2 已完成基础双端口可达性，L3 受宿主环境
限制；任何 L3 项不得由 QEMU 结果替代。

## 后续执行顺序

1. 完成 BGP、OSPF 动态 route add/withdraw 到 VPP 的证据闭环。
2. 为 QEMU lane 增加多流生成和 per-interface counter 统计。
3. 固化 VFIO、uio_pci_generic、igb_uio 三种 DPDK preflight/结果格式。
4. 冻结 Linux/VPP backend contract，并将其转为 conformance gate。
5. 进入 VLAN、VXLAN、EVPN、BFD 扩展。
