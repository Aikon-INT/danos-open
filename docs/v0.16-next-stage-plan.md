# v0.16 后续工程化任务计划

更新时间：2026-09-25

## 目标

在 topology-87 集成 gate 已通过的基础上，把当前结果固化为可重复的
contract、故障恢复和性能验收流程，再进入协议扩展。

## 阶段与完成条件

| 阶段 | 任务 | 完成条件 |
|---|---|---|
| P0 | contract 冻结 | Route/NH/NHGroup 的 add/update/delete、tombstone、依赖顺序、重试、回滚、replay 均有 conformance 证据 |
| P1 | 故障恢复 | FRR zserv 断连、FRR 重启、DANOS 重启、VPP 重启、ECMP 路径上下线均能恢复且无泄漏 |
| P2 | QEMU 固化 | 一条命令生成 Debian trixie 拓扑、运行 34 项 CTest 和统一 QEMU gate，并保存日志/版本 manifest |
| P3 | 性能 lane | QEMU e1000 功能基线、VMXNET3 smoke、PCI/VMXNET3/SR-IOV DPDK 吞吐和 ECMP 分布基线分层发布 |
| P4 | 扩展协议 | BFD → VLAN → VXLAN → EVPN，逐项补充对象模型、capability、依赖和 conformance |

## 当前基线

- CTest：34/34 PASS。
- topology-87：VPP API/stats、双路径报文、ECMP 多流/计数、VPP restart replay、
  FRR 10.3 BGP add/withdraw、OSPF Full、ZAPI 31/32 和 DPA/VPP 编程全部 PASS。
- 最终 QEMU ISO：`build/danos-vpp-dpdk-e1000-2port-final3.iso`。
- QEMU 启动脚本已生成 `run-manifest.env`，记录 commit、ISO SHA256、拓扑路径、
  端口和 UTC 时间；统一 verifier 会拒绝没有 manifest 或 digest 的运行。
- QEMU 结果不替代真实 PCI DPDK 性能结果；后者需要独立 runner 提供 PCI、HugePages、
  VPP DPDK plugin 和可控网卡绑定。
- topology-87 进一步通过 FRR daemon restart、zserv socket 恢复、BGP peer 恢复和
  VPP restart replay；FRR 重启期间产生的 zserv EOF 被作为受控断连验证，而不是
  未分类 runtime error。
- DPDK preflight 支持 `DPDK_RESULT_FILE`，输出 `PASS/SKIP/FAIL`、退出码、VPP/插件
  路径、PCI driver/BDF、PCI/VMXNET3 数量和 HugePages，供 CI 或专用 runner 归档。

## 执行顺序

1. 将 backend contract 的生命周期断言扩展为 Linux/VPP 对称 conformance。
2. 为 recovery 测试增加明确的事件时间线、超时分类和资源泄漏检查。
3. 为 QEMU lane 增加 manifest、日志归档、重复运行和失败保留机制。
4. 增加统一性能输出格式：pps、Mbps、p50/p99、CPU、丢包率、ECMP bucket。
5. 运行真实 PCI preflight；环境不满足时输出结构化 `SKIP/ENVIRONMENT-OPEN`，不得伪造 PASS。
6. 完成以上四项后再开始 BFD/VLAN/VXLAN/EVPN。

当前 P3 状态：本宿主的 `run_vpp_dpdk_lane.sh` 返回 `SKIP`（VPP binary
unavailable），因此没有把软件/QEMU结果误记为真实 PCI DPDK 性能通过。

## 发布门禁

任何扩展协议合并前必须同时满足：

- CTest 全绿；
- backend contract gate 全绿；
- topology-87 等价 QEMU gate 全绿；
- 新增对象具备 add/update/delete/restart/replay 证据；
- 性能或硬件缺失只能标记为环境开放项，不得替代成功证据。
