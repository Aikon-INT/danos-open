# v0.16 后续工程化任务计划

更新时间：2026-09-26

## 目标

在 topology-87 集成 gate 已通过的基础上，把当前结果固化为可重复的
contract、故障恢复和性能验收流程，再进入协议扩展。

## 阶段与完成条件

| 阶段 | 任务 | 完成条件 |
|---|---|---|
| P0 | contract 冻结 | Route/NH/NHGroup 的 add/update/delete、tombstone、依赖顺序、重试、回滚、replay 均有 conformance 证据 |
| P1 | 故障恢复 | FRR zserv 断连、FRR 重启、DANOS 重启、VPP 重启、ECMP 路径上下线均能恢复且无泄漏 |
| P2 | QEMU 固化 | 一条命令生成 Debian trixie 拓扑、运行 34 项 CTest 和统一 QEMU gate，并保存日志/版本 manifest |
| P3 | 性能 lane | QEMU e1000 功能基线、VMXNET3 smoke、PCI/VMXNET3/SR-IOV DPDK 吞吐和 ECMP 分布基线分层发布 |
| P4 | 扩展协议 | BFD → VLAN → VXLAN → EVPN，逐项补充对象模型、capability、依赖和 conformance |

## 当前基线

- CTest：34/34 PASS。
- topology-87：VPP API/stats、双路径报文、ECMP 多流/计数、VPP restart replay、
  FRR 10.3 BGP add/withdraw、OSPF Full、ZAPI 31/32 和 DPA/VPP 编程全部 PASS。
- 最终 QEMU ISO：`build/danos-vpp-dpdk-e1000-2port-final3.iso`。
- QEMU 启动脚本已生成 `run-manifest.env`，记录 commit、ISO SHA256、拓扑路径、
  端口和 UTC 时间；统一 verifier 会拒绝没有 manifest 或 digest 的运行。
- QEMU 结果不替代真实 PCI DPDK 性能结果；后者需要独立 runner 提供 PCI、HugePages、
  VPP DPDK plugin 和可控网卡绑定。
- topology-87 进一步通过 FRR daemon restart、zserv socket 恢复、BGP peer 恢复和
  VPP restart replay；FRR 重启期间产生的 zserv EOF 被作为受控断连验证，而不是
  未分类 runtime error。
- DPDK preflight 支持 `DPDK_RESULT_FILE`，输出 `PASS/SKIP/FAIL`、退出码、VPP/插件
  路径、PCI driver/BDF、PCI/VMXNET3 数量和 HugePages，供 CI 或专用 runner 归档。
- 多核性能脚本默认拒绝合成 TRex 数据并返回 `ENVIRONMENT-OPEN`；只有显式
  `--simulate` 才允许演示数据，不能作为 v0.16 性能验收证据。
- QEMU 拓扑支持通过 `QEMU_DATAPLANE_MODEL=vmxnet3` 切换两条 DANOS 数据面
  NIC；ISO 构建器会记录 `vpp-dpdk-device`，但 VMXNET3 真实吞吐仍须在带
  VPP/DPDK runtime、HugePages 和流量发生器的 guest lane 中实测。
- ISO 构建器支持 `VPP_DPDK_NO_RX_INTERRUPTS=1`，仅用于 DPDK polling-only
  对照；启用后必须单独标记，不能与 MSI-X interrupt-mode 结果混用。
- 2026-09-25 使用 `danos-vpp-runtime-verify:local` 构建 VMXNET3 ISO，并在
  `pc` 与 `q35`、单端口与双端口组合下启动；VPP 26.10-rc0 均在 DPDK
  VMXNET3 初始化后 SIGSEGV。该结果已保留在 topology-87 串口日志，故
  VMXNET3 lane 当前明确为 FAIL/兼容性缺陷，不得标记为性能 PASS；下一步需
  升级/修复 VPP-DPDK VMXNET3 PMD 或改用已验证的 virtio/e1000 lane 后再测吞吐。
- native `vmxnet3_plugin` 对照测试不触发 SIGSEGV，但 QEMU guest 没有可用
  中断线（`No sufficient interrupt lines (0)`）；已修正 traffic gate，`unknown
  input`/连接失败不会再被标记为 PASS。
- VMware Workstation 26.0.0 对照确认两块 VMXNET3 BDF 为 `0000:0b:00.0` 和
  `0000:13:00.0`，但 native VPP plugin 仍得到 0 条中断线；因此当前阻塞点
  是 guest PCI MSI-X 能力/分配，而不是 BDF 映射。DPDK lane 的 SIGSEGV 和
  native lane 的 MSI-X=0 均保留为失败证据，不能用 e1000 结果替代。
- 增加 DPDK `no-rx-interrupts` polling-only 变体后，VMware 实测已通过
  VMXNET3 两接口创建、link up 和双路径 ECMP FIB 初始化；该结果只关闭
  runtime 初始化门禁，不能替代 PPS、吞吐、延迟、丢包和远端多流验收。
- VMware polling lane 进一步启用 `ping_plugin` 后，VPP 内部双路径 ping 和
  两接口 TX counters 均有真实事件；宿主缺少有效 `CAP_NET_ADMIN`，无法把
  `vmnet1` 配成外部静态邻居，因此外部 host/peer 流量仍保持 OPEN。
- 已固化同一 `vmnet1` 上的项目内双 VMXNET3 peer VM（`192.168.45.2/24`、
  `192.168.46.2/24`）与 DANOS VMXNET3 polling-only DPDK VM
  （`192.168.45.3/24`、`192.168.46.3/24`）；两条路径均完成 peer→VPP、
  VPP→peer 双向 ping，VPP 接口 RX/TX 与 ECMP 两 bucket 均有真实计数。
  这关闭了远端报文 smoke 阻塞，但高强度 peer traffic generator 仍未形成
  可发布 PPS/吞吐/延迟基线。
- 复测发现并修正了一个验收缺陷：两块 VPP 接口使用同一 `/24` 时，VPP 会拒绝
  第二个地址；当前 lane 强制使用独立网段，并将地址冲突输出纳入串口证据。
- peer traffic gate 已增加 `DANOS_TRAFFIC_INTERVAL`、耗时和 pps marker；在
  100 包/10ms 的双网段复测中得到约 99.01/98.04 pps、0% loss。该结果固化
  packet-level 回归基线，线速吞吐/延迟仍必须由专用流量发生器完成。
- `danos-test/vmware/verify_vmxnet3_packet_baseline.sh` 已固化为可失败的
  packet baseline gate，默认要求双路径 marker 和最低 50 pps；它不替代真实
  DPDK line-rate/performance runner。

## 执行顺序

1. 将 backend contract 的生命周期断言扩展为 Linux/VPP 对称 conformance。
2. 为 recovery 测试增加明确的事件时间线、超时分类和资源泄漏检查。
3. 为 QEMU lane 增加 manifest、日志归档、重复运行和失败保留机制。
4. 增加统一性能输出格式：pps、Mbps、p50/p99、CPU、丢包率、ECMP bucket。
5. 运行真实 PCI preflight；环境不满足时输出结构化 `SKIP/ENVIRONMENT-OPEN`，不得伪造 PASS。
6. 完成以上四项后再开始 BFD/VLAN/VXLAN/EVPN。

当前 P3 状态：本宿主的 `run_vpp_dpdk_lane.sh` 返回 `SKIP`（VPP binary
unavailable），因此没有把软件/QEMU结果误记为真实 PCI DPDK 性能通过。

## 发布门禁

任何扩展协议合并前必须同时满足：

- CTest 全绿；
- backend contract gate 全绿；
- topology-87 等价 QEMU gate 全绿；
- 新增对象具备 add/update/delete/restart/replay 证据；
- 性能或硬件缺失只能标记为环境开放项，不得替代成功证据。
