# DANOS-Open v0.4 Interoperability Definition of Done

> 目的:把 v0.3"自证为真"(规格实现 + 自建对端验证)升级为 v0.4
> "他证为真"(外部独立实现互通)。每项检查都可由脚本或 CI 断言,
> 完成与否不靠叙述。

验收脚本:`danos-test/integration/run_v0.4_interop.sh`
外部工具:gnmic(openconfig)、grpc-go 客户端、真实 VPP。

## I 组:gNMI × 外部客户端(grpc-go / gnmic)

| ID | 检查项 | 验收标准 | 状态 |

| I5 | gnmic subscribe (STREAM) | Set 触发的 Update 在 <1s 内推送到订阅流 | ✅ |

## 执行矩阵

- aarch64 交叉编译:I1-I8 源码编译通过即可(运行时验证 x86_64)

## 环境阻塞记录

- V 组(真实 VPP)当前环境无法执行:packagecloud.io(FDio apt 源)
  SSL 证书被中间设备劫持,github.com clone 超时,Docker Hub 拉取超时。
  解锁路径:任一可用网络下 `docker run -d --privileged fdio/vpp`,
  或自建 VPP 包源后重跑 run_v0.4_interop.sh --with-vpp。
  当前 V 组的协议级证明由 vpp_proto_test(mock VPP 服务器,逐字节
  断言)承担。

## 已知限制(不阻塞验收,记录在案)

- HPACK 动态表仅解码端支持;编码端固定 literal-without-indexing
  (协议正确,仅带宽效率略低)
- gNMI Subscribe 的 updates_only / QoS 标记未实现
- TLS 终结依赖外部组件(socat/stunnel),h2c 为默认模式
## v0.5 增补

- I10 模型路径注册表(model_paths):叶子级 Get/Set 经 openconfig
  路径(如 /interfaces/interface[name=X]/config/mtu),未建模路径返回
  gRPC NotFound,只读 state 字段返回 InvalidArgument。gnmic 实测通过。
- DPA 错误码到 gRPC 状态码映射:NOT_FOUND→5,INVALID_ARG→3,其余→2。
- 错误响应补齐 :status + content-type 头(grpc-go 要求)。
- 性能基线见 v0.5_compat_matrix.md。
## v0.6 增补

- I11 守护进程形态:danos-mgrd 单命令拉起控制面(WAL 启动恢复 →
  gNMI → /metrics);kill -9 后重启配置原样恢复(P1 项的运行载体)。
- P 观测闭环:Prometheus 导出器接入 stat provider(VPP stat segment
  真查询或 mock 计数),/metrics 真实暴露 119 项指标;HTTP 服务从
  stub 变为真实现。
- 发布验收:release_check.sh(ctest + gnmic 互通 + mgrd 冒烟三道门)。

## v0.10 增补

- K4 达成:用户+网络命名空间内,mgrd 管线经真实 rtnetlink 将
  DPA 路由写入内核 FIB(`ip route` 可见 blackhole 条目)。
  无需宿主 root(unshare -Urn)。
- 墓碑追踪:desired 中删除的路由在下一次 sweep 中经 route_del
  从后端撤回(台账持有原始字节,撤回消息完全可重建);
  失败保留台账条目以便重试。
- netlink 适配器:网关路由支持(RTA_GATEWAY/RTA_OIF),
  blackhole 类型(RTN_BLACKHOLE),内核错误码透传
  (danos_netlink_last_kernel_error)。
## v0.12 增补

- I12 北向路由复合写:/routes/route[prefix=X] 经 gnmic 单命令下发
  (NH+Group+Route 单事务创建),级联删除 + 墓碑撤回内核条目。
  路径解析器支持键值内含 '/'(前缀)。gnmic 实测通过。
- K5a 升级:K4/K5 脚本中的路由下发由 C 驱动改为 gnmic 标准客户端,
  经 mgrd 管线写入真实内核(集成于 CI oci-image 冒烟环境可复现)。
## v0.13 增补

- I13 管线可观测性:programming attempted/ok/failed、reconcile
  repairs/failures、gNMI RPC 计数全部为真实值并经 /metrics 暴露
  (此前 119 项指标多为零值装饰)。实测:一次 gnmic set 后
  reconcile_total=4、programming_attempted=4、failed=0。
- I14 事件驱动收敛:store 变更 → 编程管线即时触发(≤50ms),
  轮询降级为兜底;STREAM 订阅推送改为事件驱动(去除 100ms 轮询)。
- Capabilities 模型列表与 model_paths 注册表同源(单一信源)。
