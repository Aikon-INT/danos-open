# DANOS-Open v0.4 Interoperability Definition of Done

> 目的:把 v0.3"自证为真"(规格实现 + 自建对端验证)升级为 v0.4
> "他证为真"(外部独立实现互通)。每项检查都可由脚本或 CI 断言,
> 完成与否不靠叙述。

验收脚本:`danos-test/integration/run_v0.4_interop.sh`
外部工具:gnmic(openconfig)、grpc-go 客户端、真实 VPP。

## I 组:gNMI × 外部客户端(grpc-go / gnmic)

| ID | 检查项 | 验收标准 | 状态 |
|----|--------|----------|------|
| I1 | gnmic capabilities | 输出含 "DANOS-Open DPA" 版本与 openconfig 模型,grpc-status=OK | ☐ |
| I2 | gnmic get | gnmic get / --path /interfaces 返回经 Set 写入的对象,值为合法 JSON_IETF | ☐ |
| I3 | gnmic set | gnmic set --update 写入后,gNMI Get 与 DPA store 回读一致 | ☐ |
| I4 | gnmic subscribe (ONCE) | 订阅立即收到 sync_response=true | ☐ |
| I5 | gnmic subscribe (STREAM) | Set 触发的 Update 在 <1s 内推送到订阅流 | ☐ |
| I6 | Huffman 头解码 | grpc-go 客户端(默认 Huffman 编码 header)的全部 RPC 成功 | ☐ |
| I7 | 长消息流控 | Get 返回 ≥64KB 响应,grpc-go 客户端完整接收不挂死 | ☐ |
| I8 | 并发流 | 单连接 8 个并发 RPC 全部成功 | ☐ |

## V 组:gNMI × 真实 VPP

| ID | 检查项 | 验收标准 | 状态 |
|----|--------|----------|------|
| V1 | 二进制 API 握手 | control_ping 往返成功;消息表条数 == vppctl show api 条数 | ☐ |
| V2 | 接口控制 | sw_interface_set_flags(up) 后 vppctl show interface 显示 up | ☐ |
| V3 | 路由下发 | ip_route_add_del 后 vppctl show ip fib 可见该前缀 | ☐ |
| V4 | stat segment | /sys/node/ 计数器值与 vppctl show statistics 一致量级 | ☐ |
| V5 | 垂直链路 | gnmic set 接口 up → DPA 事务 → VPP 生效,全程 <1s | ☐ |

## P 组:持久化 × 互通联动

| ID | 检查项 | 验收标准 | 状态 |
|----|--------|----------|------|
| P1 | 崩溃恢复 | kill -9 后重启,WAL 恢复的配置经 reconcile 在 VPP 中重现 | ☐ |
| P2 | 恢复幂等 | 连续两次 recover() 结果一致,store 计数不翻倍 | ☐ |

## 执行矩阵

- 本地开发机:x86_64, docker + danos-frr-test 镜像
- CI:全部 I 组(需 go 工具链)+ V 组(VPP 容器)+ P 组
- aarch64 交叉编译:I1-I8 源码编译通过即可(运行时验证 x86_64)

## 已知限制(不阻塞验收,记录在案)

- HPACK 动态表仅解码端支持;编码端固定 literal-without-indexing
  (协议正确,仅带宽效率略低)
- gNMI Subscribe 的 updates_only / QoS 标记未实现
- TLS 终结依赖外部组件(socat/stunnel),h2c 为默认模式
