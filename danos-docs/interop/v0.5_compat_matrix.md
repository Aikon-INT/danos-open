# DANOS-Open 版本兼容矩阵(v0.5)

> 目的:明确本仓库按哪些外部协议/组件版本冻结,以及升级策略。
> NOS 项目的可信度很大程度上来自对兼容性的严肃态度。

## 北向:gNMI / gRPC

| 组件 | 版本依据 | 冻结状态 | 升级策略 |
|------|----------|----------|----------|
| gnmi.proto | openconfig/gnmi master(2026-09 对齐) | 字段号已验证;proto_bytes(13)/double_val(14) 已编入 TypedValue 解码 | proto3 新增字段天然向后兼容;升级时重跑 gnmi_proto 精确字节测试 |
| gNMI Encoding | JSON(0)/BYTES/PROTO/ASCII/JSON_IETF(4) | Capabilities 宣告 JSON + JSON_IETF;实现按 JSON_IETF 值返回 | 增加 PROTO 编码需扩展 TypedValue 处理 |
| gRPC 传输 | gRPC over HTTP/2(RFC 7540/7541) | h2c + TLS 前置(socat);HPACK 含 Huffman;流控完整 | HPACK 编码端仍 literal-only(合法) |
| 验证客户端 | gnmic v0.35.0(grpc-go v1.60) | Interop DoD I1-I9 全绿 | 每次协议改动后重跑 run_v0.4_interop.sh |

## 南向:VPP 二进制 API

| 消息 | 来源 .api | 版本 | 冻结状态 |
|------|-----------|------|----------|
| sockclnt_create / create_reply | vlibmemory/memclnt.api | 2.1.0 | msg 0xF 握手 + 消息表解析,跨版本稳定 |
| sw_interface_set_flags | vnet/interface.api | 3.2.5 | 字段布局硬编码 |
| ip_route_add_del / ip_table_add_del | vnet/ip + fib/ip_types | ip 3.5.x / fib 3.x | fib_path 16 label 槽位硬编码 |
| ip_neighbor_add_del | vnet/ip-neighbor | 2.x | |
| policer_add_del | plugins/policer/policer.api | 3.0.0 | 1R2C/2R3C(RFC2698),KBPS |

已知风险与对策:

1. **msg_id 动态分配**:全部通过 sockclnt_create_reply 消息表解析,
   不硬编码 ID —— 跨版本安全。
2. **字段布局按 master 冻结**:VPP LTS 与 master 之间若字段变化
   (如 flags 由 enum 变位图),需要兼容层。对策:接入真实 VPP 后
   先跑 vpp_live_test,对失败消息做版本分支(用 get_first_msg_id /
   版本探测),而不是盲目硬编码。
3. **stat segment v2**:目录条目 32 字节布局;版本检查已存在
   (version < 2 拒绝)。

## 性能基线(v0.5,txn_scale_test,x86_64,tmpfs)

| 项 | 数值 | 备注 |
|----|------|------|
| 逐对象事务 | 0.001 ms/obj(1000 对象) | /tmp 为 tmpfs;真实盘 fsync 更高 |
| 批量事务 | 1000 对象 0.2 ms | 单事务 |
| WAL 写入(fsync each) | 1000 对象 5.5 ms | tmpfs 上限 |
| WAL 恢复 | 1000 对象 3.1 ms | 含遍历 + 建对象 |

## 升级流程

1. 改协议实现前,先在本文档登记目标版本;
2. 相应 .api 文件重新核对字段(用 WebFetch 拉取 raw 定义);
3. 重跑:ctest 全量 + run_v0.4_interop.sh(--with-vpp 如可用);
4. 精确字节断言失败即为本仓库与上游版本漂移,按升级策略处理。
